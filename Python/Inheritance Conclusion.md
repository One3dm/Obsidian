Наследование — итоги и компромиссы

Что даёт наследование (The Good)

1. **Иерархия классов** — позволяет использовать код родительских классов без дублирования.
2. **`super()`** — даёт возможность дополнить поведение родительского класса, не заменяя его полностью.
3. **Method Resolution Order (MRO)** — для одиночного наследования Python ищет методы снизу вверх: дочерний → родительский.
4. **Множественное наследование** — можно наследовать от нескольких классов (но есть свои правила MRO).


Проблемы наследования (The Bad)

1. **Неявный код (implied code)** — не всегда понятно, где определён метод: в родителе или в дочернем классе.
2. **Родительский код может измениться** — изменения в родителе могут сломать дочерние классы.
3. **Сложность поддержки** — трудно поддерживать согласованность между переопределёнными методами.


Trade-Offs: когда использовать наследование

| Плюсы | Минусы |
|-------|--------|
| ✅ Уменьшает дублирование кода | ❌ Код становится менее явным |
| ✅ Позволяет расширять функциональность | ❌ Жёсткая связь между классами |
| ✅ Упрощает добавление новых классов в иерархию | ❌ Изменения в родителе влияют на всех потомков |

Пример: иерархия классов

```
object
   ↑
ConnectionClass
   ↑
   ├── TelnetConnection
   └── SSHConnection
```

- `ConnectionClass` — общая логика (`__init__`, `host`, `username`)
- `TelnetConnection` и `SSHConnection` — специфичные реализации


Альтернатива наследованию

Иногда вместо наследования лучше использовать **композицию** (см. следующую тему). Наследование — это отношения **«is-a»** (является), композиция — **«has-a»** (имеет).


📌 Итог

```python
# Наследование — полезно, но используйте осознанно
class Parent:
    def method(self):
        return "Parent"

class Child(Parent):
    def method(self):
        return "Child"
```

| Вопрос | Ответ |
|--------|-------|
| Когда использовать наследование? | Когда есть чёткая иерархия «is-a» |
| Когда избегать? | Если связь слабая или иерархия неочевидна |
| Альтернатива | Композиция (объект содержит другие объекты) |
