Контекстные менеджеры и оператор `with`

Проблема: забываем закрывать файлы

```python
# ❌ Проблема: если ошибка, файл не закроется
f = open("config.txt")
data = f.read()
# Если здесь ошибка...
f.close()  # ...эта строка не выполнится
```

Решение: `with`
```python
# ✅ Решение: with закрывает файл автоматически
with open("config.txt") as f:
    data = f.read()
# Файл закрыт здесь, даже если была ошибка
```

Что происходит:
1. Открываем файл
2. Работаем с ним
3. **Автоматически закрываем** при выходе из блока

Почему безопасно

```python
with open("file.txt") as f:
    print(undefined_var)  # ❌ Ошибка!
    data = f.read()       # Не выполнится

# Файл всё равно закроется
```

Синтаксис
```python
with выражение as переменная:
    # работаем с переменной
    # ...
# ресурс освобождён
```

Примеры:
```python
# Один файл
with open("input.txt") as f:
    print(f.read())

# Несколько файлов
with open("a.txt") as a, open("b.txt") as b:
    print(a.read() + b.read())
```

Где ещё используется
```python
# Сетевые подключения (netmiko)
with ConnectHandler(**device) as conn:
    output = conn.send_command("show version")

# Базы данных
with sqlite3.connect("network.db") as db:
    db.execute("SELECT * FROM devices")

# Блокировки потоков
with threading.Lock():
    # критическая секция
```

Сравнение

| Без `with` | С `with` |
|------------|----------|
| `f = open(...)` | `with open(...) as f:` |
| `f.close()` вручную | **Автоматическое** закрытие |
| Риск забыть закрыть | Всегда закрывается |
| 3+ строки | 2 строки |

📌 Итог
**Всегда используйте `with` для файлов:**
```python
# ✅ Правильно
with open("file.txt") as f:
    data = f.read()

# ❌ Избегайте
f = open("file.txt")
data = f.read()
f.close()
```

**Преимущества:**
1. **Безопасно** — файл закрывается даже при ошибках
2. **Короче** — меньше кода
3. **Читаемо** — явно видно границы работы с ресурсом
