Дополнительные аспекты функций

1. Аргументы могут быть любых типов

Параметры функций не обязаны быть строками. Это могут быть числа, списки, словари и любые другие объекты.

```python
def process_data(data_list, multiplier):
    return [x * multiplier for x in data_list]

result = process_data([1, 2, 3], 10)   # список и число
```


2. Функции всегда что-то возвращают

Даже если нет явного `return`, функция возвращает `None`.

```python
def say_hello(name):
    print(f"Hello {name}")

result = say_hello("Alice")
print(result)   # None
```


3. ❌ Опасный паттерн: изменяемые значения по умолчанию

**Никогда не используйте списки, словари или другие изменяемые объекты в качестве значений по умолчанию!**

```python
# ❌ НЕ делайте так!
def bad_function(var1, var2, var3=[]):
    print(var3)
```

**Почему:** Значение по умолчанию создаётся **один раз** при определении функции, а не при каждом вызове. Если вы изменяете этот объект внутри функции, изменения сохраняются между вызовами.


✅ Правильный способ: использовать `None`

```python
# ✅ Правильно
def good_function(var1, var2, var3=None):
    if var3 is None:
        var3 = []           # создаём новый список при каждом вызове
    var3.append(var1)
    print(var3)
```

Теперь при каждом вызове создаётся **новый** список.


📌 Итог

| Правило | Почему |
|---------|--------|
| Аргументы → любые типы | Гибкость кода |
| Функции всегда возвращают `None` по умолчанию | Явное лучше неявного |
| Не использовать `[]`, `{}`, `set()` как значения по умолчанию | Изменяемые объекты сохраняют состояние между вызовами |
| Использовать `None` + проверку `if var is None:` | Безопасно и предсказуемо |
