Классы и объекты — обзор

Зачем нужны классы и объекты

Ещё один способ создавать **переиспользуемые строительные блоки** (наряду с функциями).

Проблема, которую решают классы

При использовании функций часто приходится **передавать одни и те же данные** в несколько функций:

```python
def read(telnet_conn, sleep=1.5):
    time.sleep(sleep)
    data = tn.read_very_eager().decode()
    return data

def write(telnet_conn, data):
    byte_data = data.encode()
    telnet_conn.write(byte_data)

def login(telnet_conn, username, password):
    debug = False
    prompt_terminator = r"#"
```

Здесь `telnet_conn` передаётся в **каждую функцию**. Это неудобно и загромождает код.

Решение: классы и объекты

| Концепция | Назначение |
|-----------|------------|
| **Объект** | Контейнер для **общих данных** (shared data) |
| **Методы** | Функции, которые **знают об этих данных** и работают с ними |
| **Класс** | **Чертёж** (blueprint) для создания объектов |

Вместо передачи общих данных через аргументы, мы **связываем данные и методы внутри одного объекта**.

Пример: чертёж класса (blueprint)

```python
class TelnetConn:
    def __init__(self, host, username, password):
        self.host = host
        self.username = username
        self.password = password
        self.telnet_conn = Telnet(self.host)

    def write(self, data):
        byte_data = data.encode()
        self.telnet_conn.write(byte_data)
```

- `__init__` — метод инициализации (создаёт и настраивает объект)
- `self` — ссылка на сам объект
- `self.host`, `self.username` — атрибуты (данные, привязанные к объекту)
- `write` — метод (функция, работающая с данными объекта)


📌 Итог

| Термин | Определение |
|--------|-------------|
| **Класс** | Чертёж для создания объектов |
| **Объект** | Экземпляр класса (контейнер данных) |
| **Метод** | Функция, принадлежащая классу |
| **Атрибут** | Переменная, принадлежащая объекту |
| `self` | Ссылка на текущий объект внутри класса |
