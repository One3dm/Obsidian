**Что такое инкапсуляция**

**Инкапсуляция** — это процесс добавления заголовков (и иногда трейлеров) к данным на каждом уровне модели OSI при передаче от отправителя к получателю.

**Обратный процесс (удаление заголовков)** называется **деинкапсуляцией**.

**Аналогия:** Отправка письма:
- Текст (данные) → конверт с адресом (TCP/UDP) → почтовый мешок (IP) → грузовик (Ethernet).


**PDU (Protocol Data Unit) — как называются данные на каждом уровне**

| Уровень OSI | Название PDU | Что добавляется |
|-------------|--------------|-----------------|
| **Прикладной (L5-7)** | **Data** (Данные) | Заголовок приложения (опционально) |
| **Транспортный (L4)** | **Segment** (Сегмент) — для TCP / **Datagram** — для UDP | TCP/UDP-заголовок (порты, последовательность) |
| **Сетевой (L3)** | **Packet** (Пакет) | IP-заголовок (source/dest IP, TTL, Protocol) |
| **Канальный (L2)** | **Frame** (Кадр) | Ethernet-заголовок (source/dest MAC, Type) + трейлер FCS |
| **Физический (L1)** | **Bits** (Биты) | Преобразование в электрические/оптические сигналы |

**Процесс инкапсуляции**

![[encaps.png]]

**Шаг 1 — Прикладной уровень (L5-7):**
- Пользовательские данные (например, веб-страница, файл, запрос) готовятся к передаче.
- В зависимости от приложения может добавляться свой заголовок (HTTP, FTP, DNS и т.д.).

**Шаг 2 — Транспортный уровень (L4):**
- Данные разбиваются на **сегменты** (TCP) или **дейтаграммы** (UDP).
- Добавляется **TCP/UDP-заголовок**:
  - Порт источника и назначения
  - Sequence Number (для TCP) — нумерация для сборки на приёмнике
  - Checksum (контрольная сумма)

**Шаг 3 — Сетевой уровень (L3):**
- Сегменты инкапсулируются в **пакеты**.
- Добавляется **IP-заголовок**:
  - Source IP
  - Destination IP
  - TTL (Time To Live)
  - Protocol (TCP=6, UDP=17, ICMP=1)

**Шаг 4 — Канальный уровень (L2):**
- Пакеты инкапсулируются в **кадры (Frame)**.
- Добавляется **Ethernet-заголовок**:
  - Source MAC
  - Destination MAC
  - Type (0x0800 = IP)
- Добавляется **трейлер FCS** (Frame Check Sequence) — для обнаружения ошибок.

**Шаг 5 — Физический уровень (L1):**
- Кадры преобразуются в **биты** (электрические импульсы, световые сигналы, радиоволны) и отправляются в среду передачи.

### 🔽 Процесс деинкапсуляции (на стороне получателя)

![[encap2.png]]

**Шаг 1 — Физический уровень (L1):**
- Принимает биты, преобразует их обратно в **кадры**.

**Шаг 2 — Канальный уровень (L2):**
- Проверяет **FCS** — если ошибка, кадр отбрасывается и запрашивается повторная передача.
- Проверяет **Destination MAC** — если не его, отбрасывает.
- Удаляет Ethernet-заголовок и трейлер → **пакет** передаётся на L3.

**Шаг 3 — Сетевой уровень (L3):**
- Проверяет **Destination IP** — если не его, отбрасывает.
- Проверяет TTL (если 0 — отбрасывает).
- Удаляет IP-заголовок → **сегмент** передаётся на L4.

**Шаг 4 — Транспортный уровень (L4):**
- Собирает сегменты в правильном порядке (TCP).
- Проверяет Checksum.
- Удаляет TCP/UDP-заголовок → **данные** передаются на L5-7.

**Шаг 5 — Прикладной уровень (L5-7):**
- Удаляет заголовки приложений (HTTP, DNS и т.д.).
- Передаёт чистые данные пользователю.

### 📊 Наглядный пример: `ping 8.8.8.8`

| Шаг | Данные | Добавлен заголовок |
|-----|--------|-------------------|
| 1 | ICMP Echo Request | — |
| 2 | ICMP + UDP-подобный заголовок | Port (у ICMP нет портов, но есть Type/Code) |
| 3 | IP-пакет | Source IP (твой IP), Dest IP (8.8.8.8), TTL=64, Protocol=1 (ICMP) |
| 4 | Ethernet-кадр | Source MAC (твоя сетевая карта), Dest MAC (шлюз), FCS |
| 5 | Биты | Преобразованы в электрические сигналы |

---

### 🔑 Ключевые принципы инкапсуляции

1. **Каждый уровень добавляет свой заголовок (и иногда трейлер).**
2. **Данные предыдущего уровня становятся данными (payload) для следующего.**
3. **На приёмнике заголовки удаляются в обратном порядке.**
4. **IP-адреса источника и назначения остаются неизменными на всём пути.**
5. **MAC-адреса меняются на каждом хопе (каждом L2-сегменте).**
