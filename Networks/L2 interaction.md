L2 взаимодействие

L2 (канальный уровень) отвечает за передачу кадров между устройствами в одной локальной сети (в одном broadcast-домене, в одной VLAN).

Если коротко: это всё, что происходит с кадром, пока он не встретил маршрутизатор.

Классический вопрос на собеседовании

"Что происходит, когда хост подключают в сеть?"

**Пошаговый процесс: хост подключается к сети**

1. Физическое подключение и Link Up  
2. Обучение MAC-таблицы коммутатора  
3. Получение IP-адреса (DHCP или статика)  
4. ARP для шлюза  
5. Обмен данными

Более подробно:
1. Физическое подключение и Link Up

Что происходит:
1. Пользователь вставляет сетевой кабель (витая пара) в сетевую карту хоста и в порт коммутатора.  
2. На обоих концах загораются линки (Link LED).  
3. Устройства договариваются о скорости и дуплексе (Auto-Negotiation).  
4. Порт коммутатора переходит в состояние up/up.

Структура: На этом этапе нет кадров и пакетов — только физические сигналы.

Проблемы:

· Не поднимается линк → плохой кабель, повреждённый порт, несовместимая скорость.  
· Misconfigured duplex — одно устройство в полном дуплексе, другое в полудуплексе → коллизии.

>[!tip] Всегда проверяй линк в первую очередь. Если нет линка — нет сети.

2. Обучение MAC-таблицы коммутатора

Когда хост подключается, он может начать передавать кадры (например, DHCP Discover или Gratuitous ARP). Это помогает коммутатору выучить его MAC-адрес.

Процесс обучения:

1. Хост отправляет первый кадр.  
2. Коммутатор смотрит на Source MAC в заголовке Ethernet.  
3. Добавляет запись в MAC-таблицу (CAM-таблица):  
   · MAC-адрес хоста → порт, на котором он появился  
4. Запись живёт ~5 минут, потом удаляется (тайм-аут).

 3. Получение IP-адреса (DHCP)

Если статический IP — хост сразу готов к общению.

Если динамический (DHCP) — процесс DORA:

![[L2_DHCP_DORA.png]]

(Картинка: DORA-процесс — хост → Discover (broadcast), сервер → Offer (broadcast), хост → Request (broadcast), сервер → ACK (broadcast/unicast))

| Шаг | Пакет         | Направление                | Структура                                                                                                                        |
| --- | ------------- | -------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| 1   | DHCP Discover | Хост → Broadcast           | L2: SRC MAC = хост, DST MAC = FF:FF:FF:FF:FF:FF; L3: SRC IP = 0.0.0.0, DST IP = 255.255.255.255; L4: UDP SPORT=68, DPORT=67      |
| 2   | DHCP Offer    | Сервер → Broadcast         | L2: SRC MAC = сервер, DST MAC = FF:FF:FF:FF:FF:FF; L3: SRC IP = IP сервера, DST IP = 255.255.255.255; L4: UDP SPORT=67, DPORT=68 |
| 3   | DHCP Request  | Хост → Broadcast           | L2: SRC MAC = хост, DST MAC = FF:FF:FF:FF:FF:FF; L3: SRC IP = 0.0.0.0, DST IP = 255.255.255.255; L4: UDP SPORT=68, DPORT=67      |
| 4   | DHCP ACK      | Сервер → Broadcast/Unicast | L2: SRC MAC = сервер, DST MAC = хост или FF:FF:FF:FF:FF:FF; L3: SRC IP = IP сервера, DST IP = 255.255.255.255 или IP хоста       |


4. ARP для шлюза

Когда хост получил IP, он должен узнать MAC-адрес шлюза по умолчанию:

1. Хост сравнивает свой IP и маску с IP-адресом назначения.  
2. Если адресат в другой сети — нужен MAC шлюза.  
3. Хост отправляет ARP-запрос (broadcast):  
   · «Кто имеет IP 192.168.1.1? Сообщи свой MAC»  
4. Шлюз отвечает ARP-ответом (unicast).

5. Обмен данными внутри сети

Теперь хост имеет всё: IP, MAC шлюза, IP шлюза.  
Он готов отправлять данные:

Если адресат в той же сети:

· Destination MAC = MAC адресата (узнан через ARP)  
· Destination IP = IP адресата

Если адресат в другой сети:

· Destination MAC = MAC шлюза  
· Destination IP = IP адресата (не меняется!)

✅ Итоговый ответ на вопрос: "Что происходит, когда хост подключают в сеть?"

Шаг Что происходит  
1 Физическое подключение — кабель вставлен, линк поднят, скорость/дуплекс согласованы  
2 Коммутатор учит MAC-адрес хоста из первого полученного кадра (Source MAC)  
3 Хост получает IP (DHCP DORA или статический)  
4 ARP для шлюза — хост узнаёт MAC-адрес шлюза через broadcast  
5 Связь установлена — хост может отправлять кадры внутри VLAN и через шлюз наружу

🎯 Итог

Вопрос Ответ  
Что такое L2 взаимодействие? Передача кадров в пределах одной локальной сети (одной VLAN)  
Какие протоколы работают на L2? Ethernet, ARP, DHCP, STP (для управления)  
Как коммутатор узнаёт MAC? Из Source MAC первого кадра от устройства  
Что такое flooding? Рассылка кадра на все порты, кроме входящего (когда MAC неизвестен)  
Как хост узнаёт MAC шлюза? Через ARP-запрос (broadcast)  
Как хост получает IP? DHCP (DORA) или вручную (статический)  
Что не меняется в пакете? IP-адреса источника и назначения  
Что меняется на каждом хопе? MAC-адреса источника и назначения
