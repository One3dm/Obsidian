**STP (Spanning Tree Protocol)**


Зачем нужен STP

В Ethernet-сетях с избыточными линками (резервными путями) образуются **петли (loops)**. Кадр, попавший в петлю, начинает бесконечно циркулировать, размножаться и забивать всю полосу. Это называется **broadcast storm** — широковещательный шторм. Сеть ложится за секунды.

**STP** (IEEE 802.1D) решает эту проблему: он **логически блокирует** избыточные порты, оставляя только один активный путь между устройствами. Физически кабель остаётся подключён, но трафик через заблокированный порт не идёт. Если основной путь упадёт, STP разблокирует резервный.

> [!important] STP не отключает резервные кабели физически. Он создаёт **логическое дерево без петель**.


Как работает STP (3 шага)

STP строит дерево в три этапа:

- **Шаг 1 — Выбор Root Bridge.** Корневым становится коммутатор с наименьшим **Bridge ID** (Priority + MAC-адрес). По умолчанию Priority = 32768. Если приоритеты равны, побеждает меньший MAC.
- **Шаг 2 — Выбор Root Port.** На каждом не-корневом коммутаторе выбирается один порт с наименьшим **Path Cost** до Root Bridge. Чем выше скорость, тем ниже стоимость (1 Гбит/с = 4, 100 Мбит/с = 19).
- **Шаг 3 — Выбор Designated Port.** На каждом сегменте выбирается один порт с лучшим BPDU. Все остальные порты переходят в **Blocking**.

Состояния портов классического STP (802.1D)

Классический STP имеет пять состояний:

- **Blocking** — порт не передаёт данные, не учит MAC, только принимает BPDU.
- **Listening** — порт не передаёт данные, не учит MAC, но принимает и отправляет BPDU. Длится 15 секунд.
- **Learning** — порт не передаёт данные, но учит MAC-адреса. Длится 15 секунд.
- **Forwarding** — порт передаёт данные и учит MAC.
- **Disabled** — порт административно отключён.

**Сходимость (convergence)** классического STP = **30–50 секунд** (Max Age 20s + Listening 15s + Learning 15s). Это долго .

BPDU — как общаются коммутаторы

**BPDU (Bridge Protocol Data Unit)** — служебные кадры, которыми обмениваются коммутаторы для построения дерева. Они содержат Root ID (кто сейчас корень), Path Cost до корня, Sender Bridge ID, Port ID. Root Bridge отправляет BPDU каждые 2 секунды (Hello Time). Остальные коммутаторы пересылают их дальше, обновляя информацию.


RSTP (Rapid Spanning Tree Protocol) — быстрая версия

**RSTP (IEEE 802.1w)** — замена классического STP. Главное отличие: **быстрая сходимость (сотни миллисекунд вместо 50 секунд)**.

- Вместо пяти состояний — три: **Discarding**, **Learning**, **Forwarding**.
- Появляется **Alternate Port** — это тот же заблокированный порт, но он **готов мгновенно** заменить Root Port при аварии, без ожидания таймеров.
- Сходимость RSTP — **меньше 1 секунды** .

Другие версии STP (что реально встречается на Cisco)

Помимо классического STP и RSTP, в реальных сетях (особенно на оборудовании Cisco) используются ещё несколько вариантов:

- **PVST+ (Per-VLAN Spanning Tree Plus)** — проприетарное расширение Cisco. Запускает **отдельный экземпляр STP для каждой VLAN**. Это позволяет распределять нагрузку: например, для VLAN 10 корневым будет один коммутатор, а для VLAN 20 — другой. Минус — больше служебного трафика (BPDU для каждой VLAN).

- **Rapid PVST+** — то же самое, что PVST+, но на основе **RSTP (802.1w)**. Даёт быстрое схождение для каждой VLAN. Это **режим по умолчанию** на современных коммутаторах Cisco (начиная с IOS 15.2(4)E) .

- **MSTP (Multiple Spanning Tree Protocol, 802.1s)** — стандарт IEEE. Позволяет **группировать несколько VLAN в один экземпляр STP** (instance). Например, VLAN 10, 20 и 30 могут использовать одно дерево, а VLAN 40, 50 — другое. Это снижает нагрузку на процессор и количество BPDU по сравнению с PVST+, где дерево строится для каждой VLAN отдельно.

**Что важно запомнить:** если ты настраиваешь Cisco и не менял режим специально, скорее всего, у тебя работает **Rapid PVST+**. Если сеть большая и VLAN десятки — смотри в сторону **MSTP**, чтобы не плодить сотни экземпляров STP.


Защита от петель на практике (PortFast, BPDU Guard)

STP работает на всех портах, включая те, куда подключены ПК. Это создаёт проблему: ПК не должен ждать 30 секунд, чтобы получить сеть.

- **PortFast** — порт сразу переходит в Forwarding, минуя Listening и Learning. Применяется только на **access-портах** (куда подключены ПК, принтеры).
- **BPDU Guard** — если на порту с PortFast появляется BPDU (подключили коммутатор), порт **отключается (err-disable)**. Защита от случайного подключения свитча в розетку.

> [!warning] Если включить PortFast на порту, который соединяет коммутаторы, можно создать петлю, пока STP не сработает. BPDU Guard предотвращает это.

### 🎯 Итог

- **STP** предотвращает петли L2 и broadcast-штормы.
- **Root Bridge** — коммутатор с наименьшим Bridge ID.
- **Root Port** — порт с наименьшим Path Cost до Root Bridge.
- **Остальные порты** — блокируются (Blocking/Discarding).
- **Сходимость STP** — 30–50 секунд, у RSTP — меньше 1 секунды.
- **BPDU** — служебные кадры для построения дерева.
- **PortFast** — мгновенное включение порта для конечных устройств.
- **RSTP (802.1w)** — быстрая версия STP.
- **Rapid PVST+** — режим по умолчанию на современных Cisco (RSTP для каждой VLAN).
- **MSTP** — группирует VLAN в экземпляры STP для экономии ресурсов.
