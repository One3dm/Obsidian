**Зачем нужен ARP**

**ARP** (Address Resolution Protocol) — протокол, который связывает **IP-адрес** (L3) с **MAC-адресом** (L2) в локальной сети.

**Проблема:** Устройства в сети общаются по MAC-адресам (L2), но приложения и маршрутизация работают с IP-адресами (L3). Нужен способ узнать, какой MAC-адрес соответствует нужному IP-адресу в локальной сети. Эту задачу решает ARP.

**Как работает ARP (по шагам)**

1. **ПК1 хочет отправить данные ПК2** в той же локальной сети.
2. **ПК1 проверяет свой ARP-кэш** — есть ли там MAC-адрес для IP-адреса ПК2.
3. **Если записи нет** — ПК1 отправляет **ARP-запрос (broadcast)** на MAC `FF:FF:FF:FF:FF:FF`:
   > «Кто имеет IP `192.168.1.2`? Сообщи свой MAC-адрес»
4. **Все устройства в сети получают этот запрос**, но только ПК2 отвечает.
5. **ПК2 отправляет ARP-ответ (unicast)** со своим MAC-адресом.
6. **ПК1 сохраняет запись в ARP-кэш** и отправляет данные.

**Структура ARP-пакета (кратко)**

| Поле | Что значит |
|------|------------|
| **Hardware Type** | Тип сети (Ethernet = 1) |
| **Protocol Type** | Тип протокола (IPv4 = 0x0800) |
| **Opcode** | 1 = Request, 2 = Reply |
| **Sender MAC** | MAC-адрес отправителя |
| **Sender IP** | IP-адрес отправителя |
| **Target MAC** | MAC-адрес получателя (в запросе — 0) |
| **Target IP** | IP-адрес получателя |

**ARP-кэш (таблица)**

У каждого устройства есть ARP-таблица, где хранятся сопоставления IP → MAC.

| IP-адрес | MAC-адрес | Тип | Время жизни (TTL) |
|----------|-----------|-----|-------------------|
| `192.168.1.1` | `AA:BB:CC:DD:EE:01` | Динамический | ~4 минуты |
| `192.168.1.2` | `AA:BB:CC:DD:EE:02` | Статический | Бессрочно |

**Типы записей:**
- **Динамические** — добавляются автоматически через ARP, живут ограниченное время (обычно 2-5 минут), потом удаляются.
- **Статические** — добавляются вручную, живут бессрочно. Используются для важных устройств (шлюзы, серверы).

**Команды просмотра:**
- **Windows:** `arp -a`
- **Linux/macOS:** `arp -n` или `ip neigh show`
- **Cisco:** `show arp` или `show ip arp`

**ARP для удалённой сети (через шлюз)**

Если устройство назначения **находится в другой сети**:

1. ПК1 понимает, что IP-адрес назначения — не в его подсети.
2. Он **отправляет данные на шлюз по умолчанию (Default Gateway)**.
3. Чтобы это сделать, ПК1 **выполняет ARP-запрос для IP-адреса шлюза**.
4. Шлюз отвечает своим MAC-адресом.
5. ПК1 отправляет пакет на шлюз.
6. Дальше маршрутизация работает уже на уровне IP — MAC-адреса меняются на каждом хопе.

> [!important] IP-адреса источника и назначения **не меняются** на всём пути. Меняются только MAC-адреса на каждом сегменте L2.


**Разновидности ARP**

| Протокол | Что делает | Где используется |
|----------|------------|------------------|
| **ARP** | IP → MAC (основной) | Повсеместно в Ethernet-сетях |
| **RARP** (Reverse ARP) | MAC → IP (устаревший) | Бездисковые рабочие станции (исторически) |
| **InARP** (Inverse ARP) | MAC → IP (для сетей с постоянными соединениями) | ATM, Frame Relay |
| **Proxy ARP** | Маршрутизатор отвечает за другую подсеть своим MAC | Сети, где нет правильной конфигурации шлюза |
| **Gratuitous ARP** | Устройство само объявляет свой IP/MAC | Обновление таблиц после смены IP или при конфликте адресов |

### 🛡️ ARP Spoofing (подмена ARP) — угроза

**Суть атаки:** Злоумышленник отправляет поддельные ARP-ответы, убеждая другие устройства, что его MAC-адрес принадлежит IP-адресу шлюза (или другого узла).

**Последствия:**
- Весь трафик идёт через атакующего (Man-in-the-Middle)
- Перехват паролей, сессий, данных
- DoS-атаки (отказ в обслуживании)

**Защита:**
- **Статические ARP-записи** для критических узлов (шлюз)
- **DAI (Dynamic ARP Inspection)** — функция на коммутаторах Cisco, проверяет ARP-пакеты
- **802.1X** — аутентификация в сети
- Сегментация сети (VLAN'ы)

| ОС / Устройство | Команда |
|-----------------|---------|

| **Linux/macOS** | `arp -n` или `ip neigh show` |
| **Cisco IOS** | `show arp` (просмотр), `clear arp` (очистка), `arp <IP> <MAC>` (статическая запись) |
