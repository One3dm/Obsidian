**TCP и UDP — транспортные протоколы


Транспортный уровень (L4) отвечает за **доставку данных от приложения на одном устройстве к приложению на другом**. Два основных протокола:

- **TCP** — надёжный, с установкой соединения
- **UDP** — быстрый, без установки соединения

Выбор между ними — это **компромисс между скоростью и надёжностью**.


Сравнение TCP и UDP

| Характеристика | **TCP** | **UDP** |
|----------------|---------|---------|
| **Соединение** | Устанавливает (3-way handshake) | Нет |
| **Надёжность** | Высокая (подтверждения, повторная отправка) | Нет (пакеты могут теряться) |
| **Упорядоченность** | Да (нумерация байтов) | Нет (могут приходить вразнобой) |
| **Скорость** | Ниже | Выше |
| **Размер заголовка** | 20 байт | 8 байт |
| **Контроль перегрузки** | Да (окна, таймеры) | Нет |
| **Примеры использования** | HTTP, HTTPS, FTP, SSH, Email | DNS, DHCP, VoIP, видеозвонки, стриминг |

> [!tip] **TCP** — когда важна целостность данных (веб-страницы, файлы).  
> **UDP** — когда важна скорость (звонки, видео, игры, DNS).

### 🔵 TCP (Transmission Control Protocol) — надёжность

**Определён в RFC 793.**

#### Ключевые особенности:
- **Установка соединения** — трёхэтапное рукопожатие (3-way handshake).
- **Нумерация байтов** — каждому байту данных присваивается порядковый номер.
- **Подтверждение (ACK)** — получатель подтверждает приём каждого сегмента.
- **Повторная отправка** — если подтверждение не пришло, данные отправляются снова.
- **Управление потоком** — окно (window) регулирует объём отправляемых данных.

#### Функции TCP (по RFC 793)

| Функция | Описание |
|---------|----------|
| **Мультиплексирование с использованием портов** | Позволяет принимающему хосту выбирать правильное приложение для данных на основе номера порта |
| **Восстановление после ошибок (надёжность)** | Нумерация и подтверждение данных с помощью полей Sequence и Acknowledgment |
| **Управление потоком с использованием окон** | Защищает буферное пространство и устройства от перегрузки трафиком |
| **Установление и завершение соединения** | Использует номера портов, Sequence и Acknowledgment для инициализации |
| **Упорядоченная передача данных и сегментация** | Разбивает поток данных на сегменты и доставляет их в правильном порядке |

---

#### Структура TCP-заголовка (20 байт)

| Поле | Размер (бит) | Что значит |
|------|--------------|------------|
| **Source Port** | 16 | Порт отправителя |
| **Destination Port** | 16 | Порт получателя |
| **Sequence Number** | 32 | Порядковый номер первого байта данных |
| **Acknowledgment Number** | 32 | Номер следующего ожидаемого байта |
| **Data Offset** | 4 | Длина заголовка (в 32-битных словах) |
| **Reserved** | 6 | Зарезервировано |
| **Flags** | 6 | Управляющие флаги (SYN, ACK, FIN, RST, PSH, URG) |
| **Window** | 16 | Размер окна (сколько данных можно отправить без подтверждения) |
| **Checksum** | 16 | Контрольная сумма |
| **Urgent Pointer** | 16 | Указатель на срочные данные |

#### Основные флаги TCP (Flags)

| Флаг | Название | Что значит |
|------|----------|------------|
| **SYN** | Synchronize | Начало установки соединения |
| **ACK** | Acknowledgment | Подтверждение полученных данных |
| **FIN** | Finish | Завершение соединения |
| **RST** | Reset | Сброс соединения (ошибка) |
| **PSH** | Push | Немедленная отправка данных |
| **URG** | Urgent | Срочные данные |

### 🔄 Установка TCP-соединения (3-way handshake)

![[TCPconect.jpg]]
> *(Здесь будет картинка 3-way handshake.)*

| Шаг | Направление | Флаги | Что происходит |
|-----|-------------|-------|----------------|
| **1** | Клиент → Сервер | **SYN** | Клиент: «Хочу соединиться». Sequence = X |
| **2** | Сервер → Клиент | **SYN-ACK** | Сервер: «Готов». Sequence = Y, Acknowledgment = X+1 |
| **3** | Клиент → Сервер | **ACK** | Клиент: «Соединение установлено». Sequence = X+1, Acknowledgment = Y+1 |

**Пример:** Веб-браузер (порт 49155) → Веб-сервер (порт 80).

- Клиент отправляет **SYN** (DPORT=80, SPORT=49155).
- Сервер отвечает **SYN-ACK** (DPORT=49155, SPORT=80).
- Клиент подтверждает **ACK** (DPORT=80, SPORT=49155).

> [!note] Завершение соединения происходит через **FIN** (4-way handshake).

### 🟢 UDP (User Datagram Protocol) — скорость

**Определён в RFC 768.**

#### Ключевые особенности:
- **Без установки соединения** — данные отправляются сразу.
- **Нет подтверждений** — отправитель не знает, дошло ли.
- **Нет упорядоченности** — пакеты могут приходить в любом порядке.
- **Лёгкий заголовок** — всего 8 байт.

#### Структура UDP-заголовка (8 байт)

| Поле | Размер (бит) | Что значит |
|------|--------------|------------|
| **Source Port** | 16 | Порт отправителя (может быть 0) |
| **Destination Port** | 16 | Порт получателя |
| **Length** | 16 | Длина пакета (заголовок + данные) |
| **Checksum** | 16 | Контрольная сумма (может быть 0) |

### 🔢 Порты — как приложения находят друг друга

Порты позволяют одному устройству с одним IP-адресом обслуживать несколько приложений одновременно.

| Тип портов | Диапазон | Примеры |
|------------|----------|---------|
| **Well-known** (системные) | 0–1023 | 80 (HTTP), 443 (HTTPS), 53 (DNS), 22 (SSH) |
| **Registered** (зарегистрированные) | 1024–49151 | 3306 (MySQL), 3389 (RDP) |
| **Dynamic / Private** (клиентские) | 49152–65535 | Выдаются динамически клиентским приложениям |

---

| Порт | Протокол | Приложение |
|------|----------|------------|

| **22** | TCP | SSH |

| **25** | TCP | SMTP (почта) |

| **67 / 68** | UDP | DHCP (сервер / клиент) |

### 🌐 Пример работы: запрос веб-страницы (HTTP + DNS)

![[searchWEB.jpg]]
> *(Здесь будет картинка с полным процессом: DNS-запрос → DNS-ответ → TCP-соединение → HTTP-запрос.)*

**Пошагово:**

1. **Пользователь вводит URL** (`http://www.example.com`) в браузере.
2. **DNS-запрос** (UDP, порт 53):
   - Клиент отправляет запрос на DNS-сервер: «Какой IP у example.com?»
   - Source IP: `64.100.1.1`, Dest IP: `192.31.7.1`
   - Source Port: `49161`, Dest Port: `53`
   - Используется UDP, потому что нужна быстрая доставка.

3. **DNS-ответ**: сервер возвращает IP-адрес `198.133.219.25`.
   - Source IP: `192.31.7.1`, Dest IP: `64.100.1.1`
   - Source Port: `53`, Dest Port: `49161`

4. **Установка TCP-соединения** (3-way handshake, порт 80):
   - Клиент → Сервер: SYN (DPORT=80, SPORT=49172)
   - Сервер → Клиент: SYN-ACK
   - Клиент → Сервер: ACK

5. **Передача HTTP-запроса** через TCP:
   - Данные отправляются надёжно, с подтверждениями и порядком.
6. **Получение веб-страницы**: браузер отображает сайт.

**Вывод:** DNS использует UDP (скорость), а HTTP — TCP (надёжность).

### 📋 Итоговая таблица

| Вопрос | Ответ |
|--------|-------|
| **Когда использовать TCP?** | Когда важна целостность данных (файлы, страницы, почта) |
| **Когда использовать UDP?** | Когда важна скорость (звонки, видео, игры, DNS) |
| **Как установить TCP-соединение?** | 3-way handshake: SYN → SYN-ACK → ACK |
| **Как закрыть TCP-соединение?** | 4-way handshake: FIN → ACK → FIN → ACK |
| **Что такое порт?** | Идентификатор приложения на устройстве |
| **Сколько портов всего?** | 65535 (от 0 до 65535) |
| **Размер TCP-заголовка?** | 20 байт (минимум) |
| **Размер UDP-заголовка?** | 8 байт |
