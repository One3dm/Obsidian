**Двоичная система — как компьютер видит IP**

Компьютеры работают в двоичной системе (0 и 1).  
IP-адрес `192.168.1.1` в двоичном виде:

```
11000000.10101000.00000001.00000001
```

Каждый из четырёх октетов — 8 бит.

**Таблица степеней двойки:**

| 2⁷ | 2⁶ | 2⁵ | 2⁴ | 2³ | 2² | 2¹ | 2⁰ |
|----|----|----|----|----|----|----|----|
| 128 | 64 | 32 | 16 | 8 | 4 | 2 | 1 |

**Пример перевода 192 в двоичную:**  
128 + 64 = 192 → `11000000`

**Пример перевода двоичного `10101000` в десятичный:**  
128 + 0 + 32 + 0 + 8 + 0 + 0 + 0 = **168**


**Маска подсети и CIDR (Classless Inter-Domain Routing)**

**Маска** определяет, какая часть IP — **адрес сети**, а какая — **адрес узла**.

Пример: `255.255.255.0` → двоичный вид: `11111111.11111111.11111111.00000000`
- `1` — биты сети
- `0` — биты узла

**CIDR** — краткая запись: `/24` (количество единиц в маске).

| Десятичная маска | CIDR | Количество хостов |
|------------------|------|-------------------|
| `255.255.255.0` | /24 | 254 |
| `255.255.255.128` | /25 | 126 |
| `255.255.255.192` | /26 | 62 |
| `255.255.255.224` | /27 | 30 |
| `255.255.255.240` | /28 | 14 |
| `255.255.255.248` | /29 | 6 |
| `255.255.255.252` | /30 | 2 |


Формула количества хостов

```
H = 2ⁿ - 2
```

где n — количество нулей в маске (биты узла),  
`-2` — вычитаем **адрес сети** и **широковещательный адрес (broadcast)**.

**Пример:** `/24` → нулей 8 → H = 2⁸ - 2 = **254 хоста**


**Быстрый способ расчёта подсетей (в уме)**

**Золотое правило:**

1. Определи маску. Например: `255.255.255.192` → `/26`
2. Найди последний байт маски, который не 0 и не 255. Здесь это `192`
3. Вычти его из 256: `256 - 192 = 64` → **шаг подсетей**
4. Дальше просто прибавляй шаг: 0, 64, 128, 192 — это начала подсетей в четвёртом байте.

**Для масок /23, /22 и т.д. (когда не 255 в третьем байте):**

| Маска | Байт | Шаг |
|-------|------|-----|
| `/23` (255.255.254.0) | 254 | 2 |
| `/22` (255.255.252.0) | 252 | 4 |
| `/21` (255.255.248.0) | 248 | 8 |

Принцип тот же — шаг считается в **третьем байте**.


Специальные адреса (зарезервированы)

| Адрес | Назначение |
|-------|------------|
| `0.0.0.0` | Нет IP (например, при запросе DHCP) |
| `255.255.255.255` | Широковещательный (всей сети) |
| `127.0.0.1` | Loopback (сам себе, проверка TCP/IP) |
| `169.254.0.0/16` | **APIPA** — когда нет DHCP, устройство само назначает себе адрес |


**Деление на подсети (Subnetting)**

**Зачем:**
- Экономия IP-адресов
- Безопасность (трафик между подсетями не идёт сам по себе)
- Уменьшение широковещательного шума

**Количество подсетей:**
```
N = 2ⁿ
```
где n — число заимствованных битов из хостовой части.

**Пример:** делим `192.168.25.0/24` на 4 подсети.  
Заимствуем 2 бита (2² = 4). Новая маска: `/26` (`255.255.255.192`).

| Подсеть | Диапазон IP | Broadcast | Хостов |
|---------|-------------|-----------|--------|
| 1 | `192.168.25.1 — 62` | `63` | 62 |
| 2 | `192.168.25.65 — 126` | `127` | 62 |
| 3 | `192.168.25.129 — 190` | `191` | 62 |
| 4 | `192.168.25.193 — 254` | `255` | 62 |

VLSM (Variable Length Subnet Mask) — гибкое деление

**Суть:** В разных подсетях можно использовать **разные маски** под реальные нужды.

**Пример:** Компании выделена сеть `192.168.1.0/24`.

| Отдел | Хостов | Нужно адресов | Маска | Подсеть |
|-------|--------|---------------|-------|---------|
| Бухгалтерия | 60 | 64 | /26 | `192.168.1.0/26` (1-62) |
| IT | 30 | 32 | /27 | `192.168.1.64/27` (65-94) |
| Отдел продаж | 20 | 32 | /27 | `192.168.1.96/27` (97-126) |
| Администрация | 6 | 8 | /29 | `192.168.1.128/29` (129-134) |

> [!tip] VLSM экономит адресное пространство. Без него пришлось бы выделить всем по `/26`.


Расчёт адреса сети и broadcast (по шагам)

**Дано:** IP `192.168.1.130`, маска `255.255.255.128` (/25)

**Шаг 1 — перевести в двоичный вид:**

| | Октет 1 | Октет 2 | Октет 3 | Октет 4 |
|--|---------|---------|---------|---------|
| IP | `11000000` | `10101000` | `00000001` | `10000010` |
| Маска | `11111111` | `11111111` | `11111111` | `10000000` |

**Шаг 2 — AND (побитовое умножение):**  
`1 AND 1 = 1`, `1 AND 0 = 0`

Результат → **адрес сети**: `11000000.10101000.00000001.10000000` = `192.168.1.128`

**Шаг 3 — broadcast:**  
Берём адрес сети, все биты узла в 1.  
Маска `/25` → последние 7 бит → `10000000` → `11111111` = `255`

→ **Broadcast: `192.168.1.255`**

**Проверка:**  
- Адрес сети: `192.168.1.128`  
- Доступные хосты: `129` — `254`  
- Broadcast: `192.168.1.255`

> [!tip] В одной сети находятся устройства, у которых **адрес сети совпадает**.
